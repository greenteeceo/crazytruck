## 2. How the user works (follow this)

- **Language:** the user writes Vietnamese. Answer in Vietnamese, short and concrete.
- **After every change:** build, commit, push to `claude/crane-rush-game`, and republish the artifact to the same URL.
  - Do not produce APK / AAB / zip unless asked. A zip was asked for at 3.13.
  - No PRs unless asked.
- **Commit trailer:** every commit ends with the attribution lines the harness gives. Never put model ids in commits.
- **Secrets:**
  - Never ask for, accept or write the **TikTok Client Secret**.
  - Never commit `android/cranerush-release.keystore` or `android/keystore.properties`.
- **Originality:** the user sent reference videos of Drive Mad (Fancade). Only the *genre feel* was used: air control, soft suspension, crash slow-mo, toppling walls, pushing obstacles. Do not copy its levels, UI (polaroid cards, captions, ring reticle, "Gold time", start barrier) or look.
- **The user's game-design rules so far:**
  - **No arcade assists:** no gravity tricks or floating, no pads or jumps in races.
  - **No clipping:** nothing passes through anything; no terrain hanging in the air.
  - **Finish:** a level counts only when the whole truck is past the line. There is a crowd, applause and a run-out with a barrier, so the truck never drives into the sea.
  - **Damage:** parts fly off only on a real hard hit. Dents and vibration are on.
  - **Throttle:**
    - Holding the throttle accelerates fast.
    - Holding the gas into an obstacle lifts the nose and is punished.
    - A truck standing on end can't be driven along.
    - Reverse really reverses, with a short pause before the wheels change direction, and both wheels spin.
  - **Touch:** touching in front of the truck drives forward, behind it reverses. The ◀ ▶ arrows stay. No camera zoom on touch.
  - **Level difficulty:**
    - Levels divisible by 5 (5, 10, 15, 20) are hard.
    - Pacing targets IPU ≈ 8 ad impressions per 5 minutes.
    - Each world has signature fun obstacles.
    - The late levels (17-20) have a skill section.
    - Clearing a world unlocks a nastier obstacle.
  - **Countdown:** each level has a countdown (stopwatch on the left) that stops whenever the game is stopped.
    - Seconds left at the finish pay gems.
    - Max 2 video continues; a continue keeps the exact time left.
  - **Race respawn:** a truck in trouble may struggle; it is reset only when flipped and still.
  - **Removed on request:** lives / hearts, Hint, and the "7 worlds / 140 levels" text.

## 3. Build and release

```bash
npm install
node build.mjs                    # dist/index.html, dist/artifact.html (web), dist-tiktok/ (TikTok), dashboard json
DEVTOOLS=1 node build.mjs         # same, but the TikTok package keeps Autoplay / AUTO / TEST
node hs-kit/hs-check.mjs dist-tiktok --dashboard dist-tiktok.hs-dashboard.json   # expect: 0 fail, 2 warn
(cd dist-tiktok && zip -q -X -9 ../release/CraneRush-tiktok-<ver>.zip *)        # files at the zip root
```

- **Version:** bump both `package.json` `version` (it goes into `project.config.json`) and `VERSION` in `src/main.js`.
- **The 2 expected hs-check warnings** are the parameters the user will fill in later:
  - `appid` in `project.config.json` (`build.mjs` writes `appid: ''`);
  - the Ad Unit IDs in `dist-tiktok.hs-dashboard.json`. Ids filled in by hand there are kept across builds.
- **Also still empty:** `HS_GAME_ID` / `HS_SDK_KEY` in `src/platform/config.js`. While they are empty the game runs offline: rewards come from `src/economy.js`, and there are no real ads, shop or cloud save.
- **Dev tools:** `DEV_TOOLS` is on in the web build and off in the TikTok build (esbuild `define: { __STORE__ }` in `build.mjs`). Five taps on the version line in Settings unlock them anyway.

## 4. Level pipeline (most of the work lives here)

### Where the levels come from

- `src/levels.js` holds:
  - `HANDMADE`: the first 3 levels of worlds 1-4;
  - the hand-made race tracks;
  - `SCRIPT`: 20 entries `[stretches, diff, maxT]` per level index;
  - `CLASSIC_PLANS`: world 1 laid out by hand;
  - the set tables `SETS`, `HARD_SET`, `SIGNATURE` (per world), `NASTY` (unlocked obstacle per world) and `SKILL`;
  - `autoPlan(wid, li)`, which builds the plan for worlds 2-20;
  - `genSpec`, `genCount`.
- **Placement rule in `autoPlan`:** a jump never comes right after a stretch that leaves loose objects on the road (`JUMPS` / `DEBRIS` lists). Rolling crates used to kill the run-up.
- **Duplicate names:** after generation, duplicate level names are renamed deterministically (last block in `levels.js`).
- `src/gen.js` is the segment generator: `build(def, seed, diff, { race, length, sea, base, plan })`. Plan entries can carry an argument, e.g. `'tower:crate'`, `'rollers:log'`.
- `src/builder.js` → `settle()` keeps the world physically believable:
  - it fills floating slabs down to the water;
  - piers for thin decks, posts for overhead beams;
  - a run-out + barrel barrier after the finish;
  - a barrel barrier behind the start ground, so reversing at the start can't drop the truck off.
- `src/genseeds.json`: the shipped seeds. **Changing the generator, the plans or `settle()` changes the levels, so the seeds must be validated again.**
- `src/pars.json`: par times (crane bot). The countdown is `ceil(par × k + 10)` with k = 3.2 on warm-ups, 2.5 on hard levels, 2.8 otherwise.

### Validation tools

Bundle each one with esbuild first: Node can't import the `.json` / `.jpg` files directly.

```bash
B='npx esbuild --bundle --platform=node --format=esm --log-level=error --loader:.jpg=dataurl'
$B tools/gensel.mjs --outfile=/tmp/gensel.out.mjs
$B tools/harness.mjs --outfile=/tmp/harness.out.mjs
$B tools/raceharness.mjs --outfile=/tmp/raceharness.out.mjs
```

- **`tools/gensel.mjs`: picks seeds.**
  - It keeps a shipped seed if it still passes, otherwise it searches for a new one. It writes `src/genseeds.json`, or the `OUT=` file.
  - `ONLY=classic,desert,races`: only these worlds / the races. Everything else is copied from the current file.
  - `REPICK=science-11,docks-20`: re-pick only these level ids. Every other seed is kept without checking (fast).
  - `TRUCKS=crane,taxi,...`: limit which trucks must pass. The default is all 21 variants, which is **very slow**: about 2 h per world on one core.
  - `OUT=file`: write elsewhere, so parallel runs (4 cores) don't clash; merge afterwards.
- **What worked at 3.13:**
  1. Run 4 parallel workers split by world, with `TRUCKS=crane,icecream,taxi,tractor,garbage,titan+max,rocket+max`.
  2. Merge the results.
  3. Check all 21 variants on every level. Use a script like the one below: `passable()` for each truck over `WORLDS.flatMap(w => w.levels)`.
  4. `REPICK` the failures with all 21 trucks.
  5. Repeat until 0 failures.
- **`tools/passable.mjs`:** `passable(level, spec)` tries 6 bot styles, backing up when stuck. `CHECK_TRUCKS` = the 16 trucks + 5 maxed (`crane`, `taxi`, `garbage`, `titan`, `rocket` with `+max`).
- **`tools/harness.mjs crane src/pars.json`:** drives every level and writes the pars.
  - 390 of the 400 levels are finished by the plain bot.
  - The other 10 fall back to the backing-up `passable` time, so they get long pars and a generous clock: medieval-15, medieval-18, snow-11, volcano-5, candy-20, moon-17, mars-19, autumn-12, icecave-9, toy-9.
- **`tools/raceharness.mjs`:** every race track at bot skill 1 / 0.85 / 0.7. All 32 finish.

All-truck check script used at 3.13 (bundle it the same way, then run it with truck ids as arguments, e.g. `crane rubble titan+max`):

```js
import { WORLDS } from '../src/levels.js';
import { VEHICLES, withUpgrades } from '../src/vehicles.js';
import { passable } from './passable.mjs';
const MAX = { speed: 5, power: 5, grip: 5, air: 5, stability: 5 };
for (const id of process.argv.slice(2)) {
  const [vid, mx] = id.split('+'); const v = VEHICLES.find((x) => x.id === vid); const spec = mx ? withUpgrades(v, MAX) : v;
  const bad = [];
  for (const l of WORLDS.flatMap((w) => w.levels)) { const r = passable(l, spec); if (!r.ok) bad.push(`${l.id}:${r.why}`); }
  console.log(id.padEnd(12), 'impassable', bad.length, bad.join(' '));
}
```

## 5. Physics and gameplay code map (the parts touched most)

- **`src/sim.js`: the core physics (planck.js).**
  - The drive block in `step()` handles: `upright` detection, the `heldThrough` punishment, `recover`, `braking` (force on the body, wheels keep rolling), the `dirWait` pause before reversing, the hold-to-accelerate force, and the air control.
  - Crash rules: lenient for races (`opts.lenient`).
  - Crash severity comes from the impact speed only.
  - `checkFinish` needs the whole truck past `finishX + 0.4`.
  - Soft ground: `SOFT` drag for `softsand` / `mud`.
- **`src/main.js`: all screens and game flow.**
  - Touch-side controls.
  - Countdown: `timeLimit`, `TIME_GEMS = 2`, `MAX_CONTINUES = 2`; the clock only runs while `sim.state === 'run'`.
  - Rubber-band races; the champion party; `unlockPopup` on a world clear.
  - Autoplay `makePlayer(kind)`, the test menu.
  - `OPEN_WORLDS = 20`.
- **`src/bot.js`:**
  - `makeBot(skill, seed, { race, pace })` drives the rivals;
  - `makePlayer('noob' | 'avg' | 'pro')` is the autoplay driver.
- **`src/racer.js`:** race respawn. Bots go back when they make no progress; the player only when still (`stillStuck`).
- **`src/render.js`:** three.js scene, dents (`hitCar`), crowd, puddles, soft-ground spray, and per-piece z offsets against z-fighting.
- **`src/platform/index.js`:**
  - touch input and zoom prevention (the artifact strips the viewport meta);
  - `vibrate(kind)`, `loadImage`.
